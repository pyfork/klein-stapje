# Slice S-001: When the owner deploys a release by hand, the server runs it only if its health check passes

Feature: [brief](brief.md)
Slice: 1 of walking-skeleton

## Outcome
When the owner runs `scripts/deploy.sh` on a release, the server runs that
release only if its health check passes, and otherwise goes back to the one
it was running.

## Rules

The app (`cvwriter serve`), started by systemd on its socket:

AC-1  Given the app is running and its database answers,
      when a client sends `GET /api/health` over the app's socket,
      then it gets 200 with the body `{"status":"ok"}` and nothing else.

AC-2  Given the database is stopped, or doesn't answer within 2 seconds,
      when a client sends `GET /api/health`,
      then it gets 503 within 3 seconds, as `application/problem+json`
      holding only `type`, `title` and `status`, so it names no host, role,
      database or error. A database that answers within 2 seconds gives 200
      (AC-1); one that answers after 2 seconds still gives 503.

AC-3  Given the app is running,
      when a client sends any other request, for example `GET /`,
      `GET /api/me` or `POST /api/health`,
      then it gets 404 as `application/problem+json` holding only `type`,
      `title` and `status`.

AC-4  Given `cvwriter` is run with an unknown command,
      then it exits 2 at once, writes nothing to standard output, and writes
      the Command-line error pattern (`specs/patterns.md`) to standard
      error: a line under 80 characters starting `cvwriter: `, which doesn't
      echo the command back, and at most a usage line after it.

AC-5  Given `cvwriter serve` is started without `CVWRITER_DATABASE_URL`,
      then it exits 1 at once, without serving, writes nothing to standard
      output, and writes one line to standard error in that pattern, naming
      `CVWRITER_DATABASE_URL`.

AC-6  Given `cvwriter serve` is started without a socket from systemd,
      then it exits 1 at once, without serving, writes nothing to standard
      output, and writes one line to standard error in that pattern, naming
      the missing socket.

AC-7  Given the app is running,
      when it serves,
      then it listens only on the socket systemd passed it, and opens no TCP
      or UDP port.

AC-8  Given the app starts serving,
      when it writes log lines (at least one, when it starts serving),
      then each line on standard output is one JSON object with `time`,
      `level`, `msg`, `service` equal to `cvwriter`, and `version` equal to
      the release's version; with systemd's `INVOCATION_ID` set, also
      `invocation_id` equal to it; with it unset, no `invocation_id` field.

The deploy script (`scripts/deploy.sh <release archive>`, run as root), on a
release archive made by `scripts/build-release.sh <version>`:

AC-9  Given a release archive,
      when the owner runs `scripts/deploy.sh` on it,
      then the release is unpacked to its own folder under `releases/`, its
      unit files are installed, `current` points to it, the app is restarted
      from it, its health check answers 200 within 10 seconds, and the
      script exits 0 with one line naming the version now running. This
      holds for the first release as for later ones, and earlier releases'
      folders stay.

AC-10 Given a running release,
      when the new release's health check doesn't answer 200 within
      10 seconds,
      then `current` points back to the running release, its unit files are
      installed again, the app is restarted from it and its health check
      answers 200, and the script exits 1 with one line naming the new
      version and the health check.

AC-11 Given no release has run before,
      when the first release's health check doesn't answer 200 within
      10 seconds,
      then the app and its socket are stopped, `current` doesn't exist, and
      the script exits 1 with one line naming the version and the health
      check.

AC-12 Given a release whose version is the one running, or doesn't match
      the version rule (1 to 64 characters; ASCII letters, digits, `.`, `_`
      and `-` only; starting with a letter or a digit), for example an empty
      version, `.`, `..`, `../x`, `-a`, `a b`, `a;b`, `s001-é` or 65
      characters,
      when the owner runs `scripts/deploy.sh` on it,
      then the script exits 1 with one line naming the problem, and nothing
      under `releases/`, `current` or the installed unit files changes.
      A version that keeps the rule, such as `s001_b.2` or one of 64
      characters, is deployed (AC-9).

AC-13 Given a release archive whose files are writable by group or others,
      when `scripts/deploy.sh` unpacks it,
      then nothing under its release folder is writable by group or others,
      and the files belong to the user running the script, not to the owner
      recorded in the archive: root, on the server, so the app's user can
      read the release but not change it.

The units the release carries:

AC-14 Given the release's unit files,
      then `cvwriter.socket` listens only on `/run/cvwriter.sock`, as user
      `cvwriter`, group `www-data`, mode 0660; and `cvwriter.service` runs
      `/sites/cvwriter/current/cvwriter serve` as user `cvwriter`, requires
      the socket, restarts on failure, sets `MemoryMax=` and `GOMEMLIMIT`,
      sets `CVWRITER_DATABASE_URL` to
      `postgres:///cvwriter?host=/var/run/postgresql&user=cvwriter` (peer
      authentication over the local socket, no password, no environment
      file), and sets `NoNewPrivileges=yes`, `ProtectSystem=strict`,
      `ProtectHome=yes`, `PrivateTmp=yes` and
      `IPAddressDeny=169.254.169.254`.

## Out of scope
- The pull deploy: the GitHub build, the token check, the fetch timer, the
  failed list and pruning old releases: slice 2, Deploys itself.
- nginx, the subdomain's DNS record, Access and the token check: slice 3,
  Signed in. Until then the app is reachable only through its local socket.
- The backup and `migrate` steps of `scripts/deploy.sh`, and the split of
  database roles (`cvwriter_owner`): the slice that adds the first table.
- Traces, metrics, the Grafana token and the deploy alert: slice 4,
  Telemetry. Log lines carry trace fields from then.
- Measuring memory and setting `MemoryMax=` and `GOMEMLIMIT` from it:
  slice 6, Storage and numbers. Until then they hold a starting value.
